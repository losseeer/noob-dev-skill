## personal_tool · 最小可用闭环

一句话概况：从一句抱怨（「点了没反应、刷新又没了、别人还能看到」）到一张门禁 `pass` 的需求卡。

### 关键节点

| 环节 | 这里发生了什么 |
|---|---|
| 解析 | 一句反馈里拆出「反馈缺失」「持久化」「权限」三条线索，归到一条需求 |
| 缺口 | `exception` 走 DEF-003 默认值；`non_functional` 走 DEF-009 量化 |
| 澄清 | 只有 `alternate_flow`（取消收藏）是 undecided，按推荐值放行并记复审条件 |
| 建模 | 权限部分直接落成 AC-003，因为用户已经明确表达过不满 |
| 验收 | 8 条 AC 覆盖 7 类场景，`concurrency` 在 test_notes 注明不适用原因 |
| 门禁 | 7 项检查全 pass |

### 可以照抄的地方

- `test_notes` 里「不适用 + 原因」的写法
- `permission` 写成「谁能做 + 被拒时看到什么」而不是「需要鉴权」
- 量化时延的写法：`P95 < 500ms（本地网络，单次请求）`
