# ADR-001: 本地 SQLite + 自增 ID base62 短码

- 状态: accepted
- 日期: 2026-10-16
- 关联选型: SEL-002, SEL-003, SEL-006
- 关联假设: ASM-001

## 背景

短链服务需要存储原始 URL 与短码的映射。定位卡给出的约束是 `criticality: low`、
`scale: small`、`budget: low`，需求侧没有任何性能类或不可枚举类的验收标准。

## 决策

1. 存储用 SQLite 单文件，`links` 单表。
2. 短码由自增主键转 base62 得到。
3. 框架沿用项目现有的 FastAPI。

## 理由

`budget: low` 直接排除了任何按量付费的托管存储（见 current.yaml 的 CONF-001）。
需求里没有响应时间类的验收标准，因此不引入缓存层，避免提前支付复杂度成本。
base62 自增短码比随机短码少一层碰撞重试逻辑，代价是短码可枚举。

## 代价

- SQLite 的并发写只能串行。规模上来后需要迁到 PostgreSQL，
  迁移改动集中在 `id` 类型与连接层，表结构可保持不变。
- 短码可被遍历。敏感链接场景下这是安全问题，届时改为随机短码。

## 复审条件

- 出现响应时间类验收标准 → 重新评估缓存层（SEL-004）。
- 引入账号体系或敏感链接 → 立即改随机短码（SEL-006 / ASM-001）。
- 并发写成为瓶颈 → 评估迁移 PostgreSQL。
