# 步骤 7：UI 原型（仅涉及前端 UI 时执行）

## 前置判断

`current.yaml` 的 `prototype.needed` 为 `false`，或无前端交付物时，**整步跳过**，不做任何提示性说明。

## 先问一次技术栈

每次执行本步都要问，并**必须给出推荐值**：

> 原型用什么形态产出？
> A. 纯 HTML 单文件 + 内联样式脚本（推荐）——零构建、双击即开、review 一轮最快；代价是复杂状态管理写得笨
> B. Vue 单文件——你项目已有 Vue 栈时合适
> C. React 单文件——你项目已有 React 栈时合适

用户超时或未授权时，**默认执行 A**。项目里已检出明确的 Vue / React 栈时，把推荐值换成对应那一项，
但仍要让用户有机会改。

## 产出要求

- 默认写到 `prototype/index.html`，多页面时按页拆 `prototype/pages/<name>.html`。
- **必须能直接打开就跑**：不依赖构建步骤、不依赖本地服务、数据可以 mock 在内存里。
- 页面要能演示 `tech/interfaces.yaml` 里的行为：
  - 成功分支要能看到结果
  - 每个 `error_case` 至少要有一条能触发它的输入路径
  - 涉及列表/统计的，数值要真的会变（哪怕只是内存计数）
- 没覆盖到的交互状态，在页面底部或 `_index.md` 里**显式列出留白**，不要默默略过。

## 更新两份登记

1. `current.yaml` 的 `prototype`：填 `stack`、`rationale`、`pages`（每页带 `covers` 与 `review_status`）。
   `validation_exempt: true` 表示本目录内容不进 schema 校验。
2. `prototype/_index.md`：页面清单 + 怎么打开 + review 时看什么 + 已知留白。

## 硬性约束

- **本目录内容不进 schema 校验**，只有 `current.yaml` 里的页面清单受校验。
  页面内部长什么样由 LLM 自由发挥，目标是让人 review，不是让机器验。
- 原型失败或跑不起来必须显式报告，**不许把打不开的页面当作已交付**。
- 原型不是正式 UI 实现，不要在里面写生产级状态管理或接真接口。

## 反模式

- 产出一个必须 `npm install` 才能看的东西，把 review 成本转嫁给用户。
- 页面看着像 UI 但点了没反应——那不是原型，是截图。
- 把 mock 数据写得像真实业务数据，让人误以为后端已经打通。
